# CC Dev Team - AI Agent Orchestrator

## Overview

This is a multi-agent orchestrator that coordinates a team of AI agents (PM, Architect, Engineer, QA, UI/UX, Code Auditor, Docs Auditor) to work on software development tasks together.

## Installation

Run `./scripts/install.sh` after cloning or moving the project. This is **required** because:

1. **Settings files need absolute paths** - Claude Code requires absolute paths for hooks, permissions, and includes
2. **Skills must be copied to user directory** - Skills go to `~/.claude/commands/` so agents can invoke `/worktree`, `/smart-commit`, etc.
3. **Worktrees directory must exist** - Creates `~/.cc-dev-team/worktrees/` for parallel development

### What Install Does

**Copied to standard Claude Code locations:**
| Source | Destination | Why |
|--------|-------------|-----|
| `skills/*.md` | `~/.claude/commands/` | Claude Code natively recognizes `/worktree`, `/smart-commit`, etc. |

**Generated with absolute paths (stays in orchestrator):**
| File | Why Generated |
|------|---------------|
| `agents/*/.claude/settings.json` | Hooks, permissions need absolute paths for this installation |

**Created:**
| Directory | Purpose |
|-----------|---------|
| `~/.cc-dev-team/worktrees/` | Git worktrees for parallel development |

**NOT copied (injected at runtime by wrapper):**
- `agents/*/system-prompt.md` - Injected via `--append-system-prompt`
- `agents/*/persona.md` - Included via `@persona.md` in system prompts
- `docs/*.md` - Included via `@../../docs/...` in system prompts

This separation is intentional: the orchestrator controls what each agent sees, rather than relying on Claude Code's standard config locations.

### If Things Break

If agents aren't following workflow or hooks aren't running, re-run `./scripts/install.sh` to regenerate settings with correct paths.

## Architecture

### Agent Spawning Flow

```
Dashboard → Broker (server.js) → spawns → claude-wrapper.js → Claude Code PTY
                ↑                                    ↓
                └──────── socket.io messages ────────┘
```

### Key Files

| File | Purpose |
|------|---------|
| `broker/server.js` | Central coordinator, spawns agents, routes messages |
| `tools/claude-wrapper.js` | PTY wrapper, loads system prompts, handles @includes |
| `agents/*/system-prompt.md` | Agent role definition and workflow instructions |
| `agents/*/.claude/settings.json` | Permissions, hooks, spinnerVerbs (generated by install) |
| `skills/*.md` | Interactive workflow skills |
| `docs/team-communication.md` | Shared messaging protocol |

### @includes Resolution

System prompts can include other files:
```markdown
@persona.md                        # Relative to system-prompt.md location
@../../docs/team-communication.md  # Relative path to docs/
```

The wrapper resolves these recursively before passing to Claude Code.

## Development Workflow (MUST BE FOLLOWED)

### For Features

1. **PM clarifies requirements** with human
2. **PM creates story** via `/new-feature` skill
3. **PM assigns to Architect** for technical design
4. **PM writes plan** to `.claude/plans/<issue>-<name>.md`
5. **Human approves plan**
6. **PM assigns to Engineer** with plan file path
7. **Engineer creates worktree** via `/worktree create feature/xxx`
8. **Engineer syncs workspace** via `sync-workspace engineer switch <path>`
9. **Engineer runs baseline tests**
10. **Engineer practices TDD** - write tests FIRST
11. **Engineer implements** following the plan
12. **Engineer hands off to PM** via `send-msg engineer pm HANDOFF "..."`
13. **PM routes through QA → UI/UX (if needed) → Code Auditor**
14. **Human checkpoint** after all gates pass
15. **Engineer commits** via `/smart-commit` after PM's `GO_AHEAD`
16. **Engineer merges** via `/worktree merge`

### For Bugs

1. **PM classifies bug type** (UI/Backend/Test/Architecture/Security)
2. **PM routes to specialist** (ui-ux/engineer/qa-engineer/architect/code-auditor)
3. **Specialist investigates** and proposes fix
4. **Same workflow as features** from step 6 onward

### Key Rules

- **PM never writes code** - coordination only
- **Engineer never plans** - implements from plan files only
- **All handoffs go through PM** - PM is the hub
- **Never skip quality gates** - QA → UI/UX → Code Auditor → Human
- **Always use worktrees** - never work directly on main
- **Always sync workspace** after creating worktree

## Skills

| Skill | Used By | Purpose |
|-------|---------|---------|
| `/new-feature` | PM | Create GitHub issues with user stories |
| `/worktree` | Engineer | Manage git worktrees for parallel work |
| `/smart-commit` | Engineer | Create logical atomic commits |
| `/dev-server` | Engineer | Manage development servers |

## Messaging

Agents communicate via `send-msg`:
```bash
send-msg <from> <to> <type> "<content>"
```

**Message Types:**
- `PROJECT_INIT` - Set project directory
- `TASK_ASSIGNMENT` - Assign work
- `GO_AHEAD` - Approval to proceed
- `STATUS_UPDATE` - Report progress
- `BLOCKED` - Need help
- `QUESTION/RESPONSE` - Q&A
- `HANDOFF` - Pass to next stage
- `APPROVE/BLOCK` - Quality gate results

## Troubleshooting

| Problem | Solution |
|---------|----------|
| Hooks not running | Re-run `./scripts/install.sh` |
| Skills not available | Re-run `./scripts/install.sh` |
| Wrong paths in settings.json | Re-run `./scripts/install.sh` |
| Agent not following workflow | Check system-prompt.md has correct instructions |
| Messages not delivered | Check broker is running, agents connected via socket.io |
